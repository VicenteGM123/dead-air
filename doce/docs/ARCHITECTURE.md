# DOCE · Architecture

DOCE (*Los trabajos de Heracles*) is a third-person action-adventure in Godot 4.7.2, GDScript, **Compatibility renderer
everywhere** (it ships on the web as WebGL 2). Everything is generated by code: meshes (`MeshBuilder`), animation
(code rigs, `Rig`), the island, the sound. Design: `docs/GDD.md` (Spanish). Sound names and levels: `docs/AUDIO.md`.
Combat, the chain spear, the camera and every feel number: `docs/COMBAT.md`.

This file describes the game as it is implemented after the merge of the streams (2026-10-11: the skeleton, CORE's
combat / chain spear / camera / hero rig, WORLD's Nemea, BESTIARY's beasts, UI+AUDIO): layout, autoloads, every
contract between the work streams (with real signatures), physics, input, debug arguments, how to run, render and
test, and who owns what.
Units are metres, +Y up, north is -Z, east +X. Models face **-Z** (Godot forward) with their origin on the ground
between the feet.

---

## 1. Quick start

```sh
cd doce/game
godot --path .                               # the game: the title menu ("Comenzar") -> play
godot --path . -- play=1                     # straight into play (args after "--", section 8)
godot --path . res://tools/arena.tscn        # combat test arena (-- autotest=1 quit=1: the 16-test bot)
godot --path . -- play=1 corebot=walk        # the island bot walking the slice (section 9)
godot --headless --path . --import           # (re)import after adding class_name files or assets
```

Controls (GDD; keyboard + mouse and gamepad):

| Action | Keyboard / mouse | Gamepad | Input action(s) |
|---|---|---|---|
| Move | W A S D / arrows | left stick, d-pad | `move_left/right/forward/back` |
| Camera | mouse (click the game to capture it, Esc releases) | right stick | `look_left/right/up/down` |
| Sprint | hold Shift | hold B, or click L3 (until the stick is released) | `sprint`, `sprint_toggle` |
| Jump | Space | A | `jump` |
| Dodge roll | tap Shift | tap B | `dodge` |
| Attack (3-hit combo) | left click | X | `attack` |
| Heavy attack | hold left click | hold X | `attack` (held) |
| Shield / parry | right click (hold / timed) | LT | `guard` |
| Chain spear | Q (aims where you look) | RT | `chain` |
| Lock on | Tab / middle click | R3 | `lock_on` |
| Use / grab / pet | E | Y | `interact` |
| Pause | Esc (or P) | Start | `pause` |

Shift and pad B carry both `dodge` and `sprint`: the hero resolves them (in a fight the roll starts on the press,
elsewhere a tap shorter than 0.15 s rolls and a longer hold sprints; `HeroInput`, docs/COMBAT.md 1). `attack` held =
the heavy blow, coiled out of the light blow's follow-through. E / pad Y also grabs a stunned beast (the wrestle).
The map is generated by `tools/input_map.gd` (the source of truth: edit its table, then
`godot --headless --path . -s res://tools/input_map.gd`).

## 3. Scene flow (scripts/main.gd)

`main.tscn` -> `main.gd` builds, in order: `TimeOfDay` (golden afternoon), `Sea`, the world (`_make_world()` ->
`World.new()` + `build(seed)`), `Fx`, the `Hero` at `world.player_start()`, the `CameraRig`, the `ToonScreen`, the UI
(`_make_ui()`), an `InputGate` (pause, and a "press any key" title when the UI has no title menu, work while the
tree is paused), applies the quality settings, spawns encounters, then prints `DOCE world ready in N ms` and goes
to TITLE (or PLAY with `play=1`).

```
BOOT --(world built)--> TITLE --(the UI's "Comenzar" -> main.start_game())--> PLAY
PLAY --(Game.hero_died)--> DEAD --(3 s real time)--> PLAY at Game.checkpoint.respawn_transform() or player_start()
PLAY --(main.victory(), called by the lion encounter)--> VICTORY
Esc / P / Start in PLAY: Game.set_paused(true/false) (the tree pauses; the UI gets show_pause(paused))
```

Hooks for the streams (keep `main.gd` small; override in a subclass like `tools/arena.gd` does):

| Hook | What it does now |
|---|---|
| `_make_world() -> Node3D` | `World.new()`, `add_child`, `build(int(seed))`. The arena overrides it. |
| `_make_ui()` | loads `res://scripts/ui/ui.gd`; skipped with `noui=1`. The UI root gets `show_title()`, `show_play()`, `show_pause(paused: bool)`. Its title is a menu (`ui.owns_title()` is true), so main's "any key" start stays off and "Comenzar" calls `start_game()`. |
| `spawn_encounters()` | for each `world.spawn_groups()` entry loads `res://scripts/enemies/<kind>.gd` (when it exists), creates `count` of them round `center` and calls `teleport(p, yaw)`. `dummies=1` adds three training dummies in front of the hero. |
| `show_title()`, `start_game()` | phase changes, title orbit camera, music, UI calls. |
| `victory()` | phase VICTORY, `stinger_victory`, hero rig `play("victory")`. |
| `corebot=` | with the arg, main adds `tools/nemea_bot.gd` (CORE's island bot, section 9). |
| `_wants_title() -> bool`, `_start_transform() -> Transform3D` | title on/off; start transform with the `start=`, `wade=`, `face=` debug args. |

`main.gd` fields: `tod`, `sea`, `world`, `fx`, `hero`, `cam`, `toon`, `ui`. The same objects are on `Game`
(`Game.main`, `Game.world`, `Game.hero`, `Game.camera`, `Game.fx`, `Game.tod`, `Game.sea`, `Game.ui`).

## 4. Autoloads and static helpers

| Name | Script | Kind |
|---|---|---|
| `Game` | scripts/core/game.gd | autoload (process mode ALWAYS) |
| `Sfx` | scripts/core/audio.gd | autoload (process mode ALWAYS) |

### 4.1 Game (scripts/core/game.gd)

```gdscript
signal phase_changed(phase: int)              # Game.Phase value
signal message(text: String, sub: String, kind: String)   # Game.say(); kinds used so far: "info", "altar"
signal boss_started(boss_name: String, boss: Node)
signal boss_ended(victory: bool)
signal labor_card(index: int, title: String)  # e.g. labor_card.emit(2, "La Hidra de Lerna")
signal hero_died
signal lock_changed(target: Node)             # null when the lock is released, lost or the target dies
signal paused_changed(paused: bool)

enum Phase { BOOT, TITLE, PLAY, DEAD, VICTORY }
const HITSTOP_SCALE := 0.02                   # Engine.time_scale during a hit-stop

var args: Dictionary          # debug args (section 8)
var phase: int                # Game.Phase
var paused: bool
var main, world, hero, camera, fx, ui, hud, tod, sea   # live references (untyped, duck-typed APIs); may be null
var checkpoint                # last Altar used (respawn point) or null
var capture_msec: int         # Time.get_ticks_msec() of the click that captured the mouse (not an attack)
var time_scale_target := 1.0  # normal Engine.time_scale (debug speed=N)

func arg(key: String, default = null) -> Variant
func has_arg(key: String) -> bool
func arg_f(key: String, default: float) -> float
func arg_vec3(key: String, default := Vector3.ZERO) -> Vector3    # "x,y,z"
func arg_on(key: String) -> bool                                   # "1", "true", "yes", "on"
func set_phase(p: int) -> void          # prints "DOCE phase <NAME>", emits phase_changed
func phase_name(p := -1) -> String
func is_playing() -> bool               # phase == PLAY and not paused
func world_ready(ms: int) -> void       # prints "DOCE world ready in N ms" once per run
func say(text: String, sub := "", kind := "info") -> void          # emits message
func set_paused(on: bool) -> void       # pauses the tree, frees the mouse, emits paused_changed
func hitstop(seconds: float) -> void    # freeze (ignores time_scale); overlapping calls extend it
func shake(trauma: float) -> void       # 0..1 trauma to the camera (respects Settings "shake")
func slowmo(scale: float, seconds: float) -> void   # slow motion (finishers, deaths)
func in_hitstop() -> bool
var frame_scale: float                  # the Engine.time_scale this frame's delta was made with
func real_delta(delta: float) -> float  # unscaled seconds of this frame: delta / frame_scale
```

Hit-stop and slow motion run on an unscaled frame clock (`_clock`: the wall clock in normal play, frame time in
`--fixed-fps` / `--write-movie` runs, so bots and renders see the same freeze), applied every frame in
`Game._process` (`Engine.time_scale = HITSTOP_SCALE` during a hit-stop, `time_scale_target * slowmo` otherwise). A
hit-stop asked for during a frame starts with the next one; its deadline counts from the end of the current frame,
so the frozen frames are `seconds` x the frame rate, rounded. **Code that must keep running in real time uses
`Game.real_delta(delta)`**, never `delta / Engine.time_scale` (the engine reads the scale once per frame: on the
first frame of a hit-stop `Engine.time_scale` is already 50 times smaller than the one the delta was made with).
The camera, main's respawn timer, `Rig` flashes, the UI (`Style.rdelta`) and `Sfx` all do. Debug: `feeldebug=1`
prints each hit-stop.

### 4.2 Sfx (scripts/core/audio.gd)

```gdscript
Sfx.play(sound: String, pos := Vector3.INF, vol_db := 0.0, pitch := 1.0)   # one-shot, attenuated by distance to the hero;
                                                                           # stinger_* plays from music/ on its own player
Sfx.music(track: String, fade := 1.6)                                      # crossfade; "" = silence
Sfx.current_music() -> String
Sfx.loop(sound: String, node: Node3D, vol_db := 0.0) -> Node               # looping emitter (amb/), free it to stop
Sfx.set_ambience(night: float, active := true, delta := 0.016)            # the beds' mix (Sfx calls it every frame)
Sfx.set_volume(bus_name: String, v: float)
var auto_music := true          # the music director (below); false: only Sfx.music() changes the track
var cave_override := -1.0       # 0..1 forces the cave amount (a scripted moment); -1 measures it
```
Files: `res://assets/audio/{sfx,music,amb}/<name>.ogg` (DOCE's 78 sounds, names and levels in `docs/AUDIO.md`,
generated by `doce/tools/audio`); a missing name is silently ignored. Buses are created with `AudioServer.bus_count`,
never `add_bus()` (web-fatal). By itself, every frame: the ambience beds follow the hero (`sea` by the coast, `wind`
up high, `day` outdoors, `cave` inside the Lion's cave, using the World's `coast_distance()` / `cave_amount()`), and
the music director plays `explore` on the island, `tension` within 55 m of a cave mouth, `boss_lion` between
`Game.boss_started` and `boss_ended`, silence under the victory stinger, ducked while the hero is down. Old PHAROS
names still used by CORE's calls are mapped by `RENAMES` (`title`/`day` -> `explore`, `blessing` -> `altar`,
`orb_hit`/`structure_hit` -> `chain_stick`); since the merge no call uses them (every name the code plays exists:
docs/AUDIO.md). Its fades and beds run in real time (`Game.real_delta`). Debug: `audiodebug=1` prints the mix
every 2 s.

### 4.3 Settings (scripts/core/settings.gd)

`Settings.get_v(k)`, `Settings.set_v(k, v)` (saves to `user://settings.cfg`), `Settings.shadows() -> bool`,
`Settings.apply_quality(viewport)`. Keys: `music`, `sfx` (0..1), `quality` (0 low, 1 medium = web default, 2 high:
MSAA 2x, 3D scale 1.0 / 0.75 at low, sun shadows from 1), `shake` (bool), `mouse_sens`, `pad_sens` (multipliers),
`invert_y`, `invert_x`.

## 5. Contracts between streams (as implemented)

Extend only by adding; never rename or remove. Duck typing everywhere (`has_method` / groups), so any stream can
implement a contract without depending on another stream's classes.

### 5.1 Damage

```gdscript
var hit := {
	"amount": 10.0,           # float
	"kind": &"blade",         # &"blade" | &"blunt" | &"chain" | &"grapple" | &"fire"
	"dir": Vector3,           # direction of the blow (knockback direction), world space
	"knockback": 3.5,         # m/s of shove
	"stagger": 0.3,           # seconds of stagger (>= 0.5 counts as heavy for the hero's reaction)
	"source": Node,           # who hit
}
```
Damageable nodes are in group `damageable` and implement:
```gdscript
var team: int                      # 0 hero, 1 enemies
func take_hit(hit: Dictionary) -> bool     # true if it hurt (false: dead, invulnerable, blocked, immune)
func is_alive() -> bool
```
Optional keys (all of docs/COMBAT.md 6.1; `Combat.make_hit(amount, kind, dir, knockback, stagger, source, extra)`
builds the dictionary): set by the attacker `point`, `attack`, `guard_break`, `unblockable`, `parryable`; written
back by the target inside `take_hit` (the attacker reads them after the call) `deflected` (immune: the lion vs
blades), `blocked`, `parried`, `dodged`, `shoved` (a push-only hit: `amount` 0, `knockback` > 0), `sound_done`.
Implemented by `Hero` (team 0: guard within 70 degrees, a 0.18 s parry window counted from the guard press, roll
i-frames, the lion pelt's blades x0.6, knockback, hit / hit_heavy reactions, shake + hit-stop, invulnerability
max(0.35, stagger + 0.1) s) and `Enemy` (team 1, see 5.10). The attacker's side of the feel (hit-stop, shake, nudge,
flash, sounds) is `HeroMelee` for the hero's blows; enemies call `Game.hitstop()` / `Game.shake()` themselves.

### 5.2 Lock-on

Group `lockable` + `func lock_point() -> Vector3` (world point the camera frames). `Enemy` adds itself; dead
enemies leave the group. `CameraRig` picks the target and emits `Game.lock_changed(target)` (5.9).

### 5.3 Chain spear anchors

Group `chain_anchor` and:
```gdscript
func chain_point() -> Vector3              # where the spearhead bites (world)
func chain_kind() -> StringName            # &"ring" fixed: the hero zips to it · &"light": pulled to the hero ·
                                           # &"heavy": the hero is pulled to it · &"boulder": dragged along the ground
func on_chain_attach(hero: Node) -> void
func on_chain_pull(hero: Node, dir: Vector3) -> void     # dir: the pull direction (normally towards the hero)
func on_chain_release(hero: Node) -> void
```
Kinds and what the hero does (docs/COMBAT.md 4): `&"ring"` zips him to it (onto a ledge just above it with a climb,
down at the foot of its standing stone when walkable ground is at most 1.9 m under where he would hang, else he
hangs from it); `&"heavy"` pulls him to it; `&"light"` is yanked to land staggered in front of him; `&"beast"` slides
`chain_slide` m along the pull and is stunned if it slams into the world or the boulder on the way (the lion's
pillar rule; the slide bends up to 25 degrees towards a pillar in reach); `&"boulder"` is hauled while the chain
button is held. Optional `chain_normal() -> Vector3` (the side the hero hangs on; ChainRing has it).
Implemented by `ChainRing` (`&"ring"`, a glint on attach; `ChainRing.new(stone_height)` on a standing stone,
`ChainRing.new(0.0, true)` mounted on a wall), `Boulder` (`&"boulder"`: dragged at 2.4 m/s while pulled, rolls and
scrapes with dust and the `boulder_drag` loop, jams with `boulder_thud` in an opening narrower than itself;
`is_blocking(point, radius)`), `Enemy` (`chain_weight`: `&"light"`, `&"heavy"`, `&"beast"`), `TrainingDummy`
(posts `&"heavy"`, sacks `&"light"`). The spear (`ChainSpear`) throws at the aim assist's pick
(`Hero.chain_candidate`: the best `chain_anchor` within 22 m in a cone round the camera's forward, in line of
sight), flies at 50 m/s, bites the first anchor it touches and comes back to the left fist; its chain bends round
the world instead of passing through it. On Nemea the three rings of the broken passage are the only crossing to
the thumb, the ridge meadow and the cave (5.5).

### 5.4 Interactables (scripts/core/interactables.gd)

Register with `Interactables.add(self)` in `_ready` and `Interactables.remove(self)` in `_exit_tree`. Duck-typed:
```gdscript
func can_interact(hero: Node) -> bool
func interact_position() -> Vector3
func interact_range() -> float                      # metres (XZ)
```

## 6. Physics

**Engine: Jolt Physics** (`physics/3d/physics_engine="Jolt Physics"`, 60 ticks/s). Both engines were exported to
the web (single-threaded WebGL 2 build) and run through `tools/phys_test.gd` in headless Chromium: rays vs
`height_at()` max error 0.000 m, hero on the floor after settling, 12.4 m walked, PASS with both; physics cost per
frame while walking 3.5 ms (Jolt) vs 2.7 ms (GodotPhysics3D) on the CPU-emulated test machine. Jolt (built into Godot
since 4.4) is kept because it is the more robust engine for what DOCE leans on: character contact on heightmaps and
trimeshes (`move_and_slide` motion queries use Jolt's enhanced internal edge removal, on by default:
`physics/jolt_physics_3d/motion_queries/use_enhanced_internal_edge_removal`, so the hero does not snag on triangle
edges), and stable contacts for movable bodies (the boulder, the lion against pillars). Re-run
`?dev=1&play=1&phystest=1` on the web after any physics change.

Layers (names in project.godot; Godot's bit value in brackets):

| Layer | Name | Who is on it | Collides with (mask) |
|---|---|---|---|
| 1 [1] | world | terrain, rocks, trunks, houses, pier, pillars, altars, ring stones, arena | — (static) |
| 2 [2] | hero | Hero capsule | world, enemies, movable (1 \| 4 \| 8) |
| 3 [4] | enemies | Enemy subclasses (dead bodies: layer 0, mask world) | world, hero, enemies, movable (1 \| 2 \| 4 \| 8) |
| 4 [8] | movable | Boulder | world, hero, enemies, movable (1 \| 2 \| 4 \| 8) |
| 5 [16] | triggers | Area3D zones (cave mouths, encounter triggers): monitor the hero with mask 2 | — |

The camera's arm (its own sphere cast) tests layer 1 only: foes never push it (they fade in front of the lens) and
the boulder does not either. Rules: nothing passes through anything (weapons, feet, props) — use
real collision for everything solid, keep visuals interpolated (hero and enemies draw a top-level rig between
physics ticks), and check rigs with `tools/clip_check`.
